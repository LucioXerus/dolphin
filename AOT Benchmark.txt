  The key distinction: AOT vs JIT differ in when translation happens, not in what runs

  Both backends produce and execute the same kind of translated x86 code. The difference is timing:
  - JIT translates each PowerPC block the first time it's hit, then caches it. After that, it runs from the cache.
  - AOT front-loads that translation so the blocks are ready before execution.

  Once a block is compiled, both run identical cached machine code. So in steady state — same scene, hot blocks already compiled — there's nothing left to differentiate them.

  The profile proves this directly

  I grepped both uncapped runs for the recompiler's compilation functions (Jit64::DoJit, FinalizeBlock, EmitStore, SafeLoadToReg):

  Where the difference actually lives — and why I didn't capture it

  AOT's payoff is in compilation transients, not steady state:
  - game boot / loading a level
  - entering a new area, a cutscene, a new visual effect — anything that hits cold PowerPC code

  At those moments JIT has to compile a burst of new blocks, which shows up as short CPU spikes and frame-time stutter/hitches. AOT pays that cost ahead of time, so it stays smooth. My methodology — 30s parked in one steady scene —
  deliberately sat between those transitions, so both looked identical. That's the measurement's blind spot, not a property of the emulator.

  So the honest answer

  - Steady-state CPU usage: no difference — and that's the expected, correct result.
  - Transient CPU spikes / stutter on new code: that's where AOT should win, and I haven't measured it yet.
